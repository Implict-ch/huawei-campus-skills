# /hw-ask — 直接答疑

## 流程

1. 判断 **阶段**（投递|机考|测评|面试|Offer）和 **类型**（流程|准备|技术|机制）
2. **按优先级检索** `knowledge/`（见下节）；Grep 关键词时**先搜高优先级路径**，平台有答案则以其为主，牛客/小红书仅作补充或交叉验证
3. **政策类**（机考分值、通过线、投递对象、机会次数、测评门槛）：优先读 `knowledge/exam/exam-format.md`、`exam-overview.md`（`policy_effective: 2026`）。面经里 100/200/300、150 分通过等**历史表述不可当作现行政策**；若多条面经政策矛盾，**以日期最新者为准**
4. **只根据**检索到的条目回答；不足则明说「知识库无法确认」，禁止编造内部机制
5. 涉及手撕题推荐（如 `/hw-match` 或用户明确要求练手撕）时，读 `knowledge/coding-problems/hot100/index.json` 取 `source_url`；**面向客户的正文只输出题目标题与自然理由，不写索引路径或「均来自…」类说明**

## 检索优先级（回答侧重顺序）

| 优先级 | 路径 | 说明 |
|--------|------|------|
| **1** | `knowledge/process/platform-*.md` | CodeFun2000 流程/题库说明 |
| **1** | `knowledge/experiences/platform/` | CodeFun2000 站内面经（`source_grade: A`） |
| **1** | `knowledge/coding-problems/hot100/` | 手撕题索引与题面（推荐链接须用 `hot100/index.json`） |
| **1** | `knowledge/videos/segments/` | 塔子哥 B 站公开课切片（含时间段）；**引用前必须 Read 片段正文并核对与问题相关** |
| **2** | `knowledge/exam/` | 精编政策/流程卡片（含 `policy_effective`） |
| **2** | `knowledge/wiki/compiled/` | 面经聚合 Wiki（`compile_wiki.py` 生成，多源摘要） |
| **2** | `knowledge/application/`、`assessment/`、`interview/`、`roles/` | 其他结构化卡片 |
| **3** | `knowledge/experiences/hw-exp-*-nc-*.md` | 牛客面经全文 |
| **3** | `knowledge/experiences/hw-exp-*-xhs-*.md` | 小红书面经全文 |

**合成答案时**：平台（优先级 1）与精编/编译 Wiki（优先级 2）优先写入「结论」和「具体怎么做」；**政策类**必须先读 `exam/` 带 `policy_effective` 的卡片，再用 `wiki/compiled/` 看面经侧信号；全文面经仅在需个案或交叉验证时 Read，并**降级表述**（如「另有牛客面经提到…」）。

## B 站视频引用（强制相关度校验）

Grep 命中 `knowledge/videos/segments/` **不等于**可以引用。每条 B 站来源必须过以下关卡，**任一不满足则不要写该条**（宁缺毋滥，改用 CodeFun2000 或省略自有视频位）。

**Agent 内部**（维护者用语，**勿写入面向客户的回答**）：

1. **Read 片段全文**：打开命中的 `hw-vid-*.md`，阅读 frontmatter 下方**片段正文**（不是只看标题、`stage` 或集名）。
2. **主题重合**：正文里须出现与用户问题/本回答结论**同一具体话题**的讲解（如问「机考通过是否有面试」→ 须谈到机考通过与面试安排的关系；不能只因同属「机考」就引用刷题技巧片段）。
3. **时间段忠实**：`MM:SS–MM:SS` 与 `?t=` **必须**取自该片段 frontmatter 的 `time_range`、`time_start_sec`（整秒），**禁止**自编、合并多片段、或沿用示例里的时间。
4. **一条片段一条引用**：每次只引用一个 segment 文件；链接用该片段 `sources[0].url` 或 `bvid` + `time_start_sec`。
5. **引用前自检**（内心核对，勿写入回答）：「若用户只看我标注的这几分钟，能否听到与结论直接相关的内容？」答否则换片段或**不写 B 站**。

**面向客户**（依据与边界里的 B 站条目）：

- 格式仍为：`[A] 塔子哥公开课 [集标题](url?t=秒) — B站 **MM:SS–MM:SS**`
- **默认只写这一条**，不在括号里解释「为何选这段」；相关内容应已体现在「结论/具体怎么做」正文中
- 若必须补半句，用自然口语：**「该段讲到…」「公开课里谈到…」**；**禁止**出现 **「字幕」** 及 **「字幕明确/提到/写道」** 等机械表述
- ❌ `（字幕明确按投递→笔试→测评→面试讲全流程）`
- ✅ `- [A] 塔子哥公开课 [从投递到入职全流程解析](url?t=120) — B站 **02:00–04:00**`（必要时括号：`（谈到笔试后还有测评、面试等环节）`）

❌ 问流程/门槛，却贴「刷题方法」「算法题型」时间段  
❌ 只匹配到 `stage: exam` 但片段正文未谈该问题  
❌ 从 episode 标题猜内容、未 Read 片段就写时间段  
✅ 片段正文与结论同主题，且时间段与 frontmatter 一致

## 来源引用规则（回答输出 vs 知识库文件）

**知识库里的面经文件不改**：牛客/小红书/frontmatter 中的 `sources[].url` **必须保留**在仓库内，供维护者追溯。

**面向客户的「依据与边界」**：

| 来源类型 | 回答里是否带 URL | 输出格式示例 |
|----------|------------------|--------------|
| **CodeFun2000**（`platform: codefun2000`、`codefun2000.com` 链接、platform 流程/手撕） | **是** | `[B] [华为AI实习入池面经](https://codefun2000.com/ide/P2528) — CodeFun2000` |
| **B 站视频**（`platform: bilibili`，`knowledge/videos/segments/`） | **是** | `[A] 塔子哥公开课 [机考备考指南](https://www.bilibili.com/video/BV1zJNG61EW8?t=366) — B站 **06:06–08:08**` |
| **牛客面经** | **否** | `[C] 牛客面经《26年校招华为笔试机试-高频问题》` |
| **小红书面经** | **否** | `[C] 小红书面经《华为暑期实习全流程经验分享》` |

- **CodeFun2000 与 B 站（自有内容）** 在回答中输出 Markdown 可点击超链接
- **B 站**：固定证据等级 **`[A]`**；链接前须写 **「塔子哥公开课」**，格式：`[A] 塔子哥公开课 [集标题](url?t=秒) — B站 **MM:SS–MM:SS**`
- **牛客/小红书（第三方）**：只写平台名 + 标题，**禁止**在回答中粘贴 nowcoder.com / xiaohongshu.com 链接
- 同一结论若自有内容与面经冲突，**以自有内容/多源一致口径为准**，面经标注为个案或旧口径
- **内部结构化卡片**（`knowledge/exam/` 等）仅作 Agent 检索用；**禁止**在「依据与边界」写出文件名、卡片 id、路径或「政策卡片」「知识库」等内部用语——边界说明用**纯文字一句**（不带 `[A/B/C/D]`），出处用下列来源条目呈现

### 「依据与边界」条目顺序（固定最多 4 条来源）

| 位置 | 来源 | 是否带链接 | 说明 |
|------|------|------------|------|
| **第 1–2 条** | 自有：CodeFun2000 / B 站 / 平台流程 / 手撕题 | **必须带链接** | 优先选与结论最直接相关的 2 条；**B 站须过「B 站视频引用」相关度校验**；无相关片段则不凑 B 站 |
| **第 3–4 条**（有则写） | 牛客 / 小红书面经 | **不带链接** | 作补充或交叉印证；没有则不凑数 |

**禁止**在「依据与边界」里把牛客/小红书排在自有来源之前；**禁止**自有来源超过 2 条仍不写牛客/小红书却堆满第三方。

### 「依据与边界」禁止出现的写法（面向客户）

❌ `exam-after-passing 政策卡片`、`knowledge/exam/`、`hw-exp-…`、`知识库无法确认` 以外的内部路径/id  
❌ `政策卡片`、`结构化卡片`、`库内卡片`  
❌ 复述 A/B/C/D 等级定义（如「说明属于：官方公开信息…」）  
❌ `（自有）`、`（若有）`、`来源 1（自有）` 等内部标签  
❌ B 站来源后写「字幕…」「字幕明确…」等字样  
✅ 首条边界说明纯文字、不带等级；来源条目标 `[A/B/C/D]`，例如：`[B] [标题](url) — CodeFun2000`

## 证据等级（Agent 打标标准，勿向客户复述）

以下四级**仅用于**给每条依据标 `[A]` `[B]` `[C]` `[D]`，**禁止**在回答里粘贴「说明属于：…」等定义原文。

| 等级 | 含义 | 典型来源 |
|------|------|----------|
| **A** | 官方公开信息；塔子哥 B 站公开课 | 华为招聘官网、机考邮件/系统页；`knowledge/videos/segments/` |
| **B** | 多份候选人经验 | 多份面经一致；CodeFun2000 与多条面经交叉印证 |
| **C** | 单一候选人经验 | 单份牛客/小红书面经；单条 CodeFun2000 站内面经个案 |
| **D** | 无法验证的推测 | 无检索依据；过期/矛盾且无法核实 |

打标规则：**仅来源条目**标 `[A/B/C/D]`；**首条边界说明**为纯文字一句，**不写等级**。**B 站塔子哥公开课固定 `[A]`**；牛客/小红书单篇通常 **`[C]`**；CodeFun2000 按 B/C 视是否多源印证。

## 输出格式

```markdown
## 结论
[1–3 句直接回答]

## 具体怎么做
1. …

### 依据与边界

机考通过仅表示达到笔试门槛，不等于一定安排面试；后续还受测评、部门 HC 等影响。（可选：纯文字边界一句，**不带 [A/B/C/D]**）
- [B] [标题](https://codefun2000.com/ide/Pxxxx) — CodeFun2000
- [A] 塔子哥公开课 [集标题](https://www.bilibili.com/video/BVxxx?t=366) — B站 **06:06–08:08**
- [C] 牛客面经《…》
- [C] 小红书面经《…》

## 相关提醒
[仅 1–2 条相关点]
```

## 禁止

空话开头；不检索答机制类问题；复制受版权保护的第三方题库正文；在回答中输出牛客/小红书外链；在「依据与边界」写出知识库文件名、卡片 id 或「政策卡片」等内部描述；向客户复述 A/B/C/D 等级定义说明；写 **`（自有）`**、**`来源 N（自有）`** 等标签；**未 Read 片段正文或未核对主题重合就引用 B 站时间段**；**自编或与片段 frontmatter 不符的 MM:SS–MM:SS**；**在面向客户的回答中出现「字幕」二字**。
